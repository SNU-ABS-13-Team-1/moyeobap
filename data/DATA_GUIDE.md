# 모여밥 음식점·메뉴 데이터 작성 가이드

> **문서 상태: 가작성안(Draft)**
>
> 이 문서는 팀이 수집한 음식점과 카페 자료를 같은 형식으로 정리하기 위한
> 기준입니다. 실제 데이터와 운영 방식을 확인한 뒤 팀 합의에 따라 수정할 수
> 있습니다.

## 1. 기본 원칙

수집한 원본과 앱에서 사용하는 정리본을 구분합니다.

- `시흥캠퍼스_식당카페_조사표_통합.xlsx` (저장소 루트): **최종 조사 데이터.**
  음식점·카페 정보를 여기 하나로 모읍니다.
- `조사표_원본/`: 빈 템플릿과 개인별 조사표 등 작업 중간 산출물
- `data/<캡처폴더>/extracted.json`: 배민 화면 캡처에서 뽑아낸 매장·메뉴 원본
- `data/restaurants.csv`: 검토가 끝난 음식점·카페 정보
- `data/menus.csv`: 앱에 표시할 메뉴 정보
- `data/sources.csv`: 데이터 출처와 확인 날짜

원본 자료에는 수집 당시의 정보를 최대한 보존할 수 있습니다. 앱용 정리본에는
현재 화면에 필요한 필드만 넣습니다.

```text
시흥캠퍼스_식당카페_조사표_통합.xlsx   ← 최종 데이터
조사표_원본/                        ← 템플릿·개인 조사표
data/
├─ capture_GJ_v2/          (캡처 원본 + extracted.json)
├─ dossier sans titre/
├─ 최지원카페2차/
├─ restaurants.csv
├─ menus.csv
├─ sources.csv
└─ DATA_GUIDE.md
```

## 2. 음식점·카페 정보

`restaurants.csv`에는 음식점이나 카페 한 곳을 한 줄로 작성합니다.

```csv
restaurant_id,name,type,category,image_url
rest_001,○○식당 배곧점,restaurant,한식,
cafe_001,○○커피 배곧점,cafe,카페,
```

필드 규칙:

- `restaurant_id`: 음식점·카페 고유 ID입니다. 중복되거나 변경되면 안 됩니다.
- `name`: 지도나 주문 페이지에서 확인한 지점명을 그대로 작성합니다.
- `type`: 음식점은 `restaurant`, 카페는 `cafe`로 작성합니다.
- `category`: 조사표의 소분류 값을 그대로 사용합니다. 배달의민족 '음식배달 홈'
  카테고리 15종에서 음식 분류가 아닌 도시락·야식을 뺀 13종입니다.

  | 대분류 | 소분류 |
  |---|---|
  | `restaurant` | 분식, 중식, 패스트푸드, 치킨, 한식, 피자, 찜·탕, 돈까스·회, 양식, 아시안, 고기, 족발·보쌈 |
  | `cafe` | 카페·디저트 |

  가운뎃점은 `·`(U+00B7)로 통일합니다. 배민은 한 가게를 최대 3개 카테고리에
  등록하지만, 조사표는 매장당 1개만 부여합니다.
- `image_url`: 사용 허가를 확인한 대표 이미지의 로컬 경로나 `https`
  주소입니다. 확인하지 못했다면 비워둡니다.

## 3. 메뉴 정보

`menus.csv`에는 메뉴 한 개를 한 줄로 작성합니다.

```csv
menu_id,restaurant_id,name,price,image_url
cafe_001_menu_001,cafe_001,(아이스)아메리카노,2500,
cafe_001_menu_002,cafe_001,(핫)아메리카노,2000,
rest_001_menu_001,rest_001,김치찌개,9000,
```

필드 규칙:

- `menu_id`: 전체 메뉴에서 중복되지 않는 고유 ID입니다.
- `restaurant_id`: `restaurants.csv`에 존재하는 음식점·카페 ID만
  사용합니다.
- `name`: 사용자가 메뉴를 구분할 수 있는 실제 메뉴명입니다.
- `price`: 쉼표와 `원`을 제외한 정수로 작성합니다. 예: `4500`
- `image_url`: 사용 허가를 확인한 메뉴 이미지의 로컬 경로나 `https`
  주소입니다. 확인하지 못했다면 비워둡니다.

메뉴 정리 규칙:

- 앱에는 이미지, 이름과 가격만 표시하므로 설명은 최종 파일에 넣지 않습니다.
- HOT과 ICE가 별도 상품이거나 가격이 다르면 별도 메뉴로 작성합니다.
- 동일한 카페의 같은 메뉴를 중복해서 넣지 않습니다.
- 샷 추가, 시럽 추가, 휘핑 추가, 원두 변경처럼 단품 주문이 불가능한 항목은
  `menus.csv`에서 제외하고 원본에만 보관합니다.
- 세트 상품처럼 단품으로 실제 주문할 수 있는 항목은 별도 메뉴로 작성할 수
  있습니다.

## 4. 출처와 확인 날짜

`sources.csv`에는 가격과 메뉴를 어디에서 언제 확인했는지 기록합니다.

```csv
restaurant_id,source_url,checked_at,note
cafe_001,https://example.com/place/1,2026-07-23,
cafe_002,https://example.com/place/2,2026-07-23,
```

필드 규칙:

- `restaurant_id`: 출처가 연결되는 음식점·카페 ID입니다.
- `source_url`: 실제로 확인한 화면입니다. 배민 앱처럼 URL이 없는 화면은
  `배민 앱 / 매장명 / 확인 화면`처럼 어디서 봤는지 알 수 있게 적습니다.
- `checked_at`: 정보를 확인한 날짜이며 `YYYY-MM-DD` 형식으로 작성합니다.
- `note`: 가격 변동 가능성이나 일부 메뉴 누락 등 공유할 내용을 작성합니다.

출처가 여러 개라면 같은 `restaurant_id`로 여러 줄을 작성할 수 있습니다.

## 5. 이미지 작성 규칙

- 외부 이미지 주소는 `https`만 최종 데이터에 사용합니다.
- `http` 주소는 앱용 파일에 그대로 넣지 않습니다.
- 이미지의 저작권과 사용 허가가 불확실하면 `image_url`을 비워둡니다.
- 출처 확인을 위해 원본 CSV에 외부 이미지 주소를 보관할 수 있습니다.
- 이미지가 없는 메뉴는 앱에서 공통 임시 이미지를 표시합니다.

## 6. 수집 경로

데이터 수집 경로는 **하나로 통일합니다.**

> 배달의민족 앱 화면을 직접 캡처 → 이미지를 AI에 전달해 OCR로 항목 추출 →
> 조사표 엑셀에 기입 → 검수 후 `restaurants.csv`·`menus.csv`로 정리

지켜야 할 것:

- **자동 수집 도구를 쓰지 않습니다.** 크롤러, 스크래핑 스크립트, HTML 저장 후
  파싱하는 방식 모두 포함입니다.
- AI에 이미지를 넘기기 전에 **리뷰 작성자 닉네임·프로필 사진 등 개인정보
  영역을 크롭하거나 가립니다.**
- 엑셀 전사가 끝난 **캡처 원본은 폐기합니다.** 저장소에는 `.gitignore`로
  제외돼 있습니다.
- 수동으로 제거하거나 변경한 항목이 있다면 이유를 `note`에 적습니다.
- 결과 파일에 로그인 정보, 주문 내역, 결제 정보 등 개인정보나 민감정보가
  포함되지 않았는지 확인합니다.

> **폐기된 경로:** 네이버 지도 페이지 HTML을 수동 복사해 스크립트로 CSV를
> 만들던 방식은 사용하지 않습니다. 관련 스크립트(`scripts/parse_naver_menu.py`)와
> 원본·파생 파일은 2026-08-10자로 저장소에서 삭제했습니다. 되살리지 마세요.

## 7. CSV 공통 규칙

- 파일 인코딩은 UTF-8을 사용합니다.
- 첫 줄에는 정해진 영문 필드명을 작성합니다.
- 셀 병합, 중간 제목 행, 빈 줄을 사용하지 않습니다.
- 값 앞뒤의 불필요한 공백을 제거합니다.
- 확인하지 못한 값은 임의로 채우지 않고 빈 값으로 둡니다.
- 최종 CSV에는 원본에만 필요한 설명이나 대표메뉴 표시를 넣지 않습니다.

## 8. Pull Request 검수 목록

데이터 Pull Request를 올리기 전에 다음 항목을 확인합니다.

- [ ] 모든 음식점·카페의 `restaurant_id`가 고유한가?
- [ ] 모든 메뉴의 `menu_id`가 고유한가?
- [ ] 모든 메뉴가 존재하는 `restaurant_id`에 연결되어 있는가?
- [ ] 가격이 쉼표와 `원`이 없는 숫자로 작성되어 있는가?
- [ ] 같은 음식점·카페의 동일 메뉴가 중복되지 않았는가?
- [ ] 단품 주문이 불가능한 추가 옵션이 제외되었는가?
- [ ] 출처 URL과 확인 날짜가 기록되어 있는가?
- [ ] 이미지가 허용된 로컬 경로나 `https` 주소인가?
- [ ] 이미지 사용 권한을 확인했는가?
- [ ] 개인정보, 로그인 정보 또는 민감정보가 포함되지 않았는가?
- [ ] AI에 넘긴 캡처에서 개인정보 영역을 가렸고, 전사 후 원본을 폐기했는가?

검수 과정에서 발견한 예외는 삭제하거나 추측해서 고치지 말고 Pull Request
설명에 남겨 팀원과 함께 결정합니다.
