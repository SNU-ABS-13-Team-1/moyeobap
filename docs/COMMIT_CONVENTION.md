# 커밋 컨벤션

이 문서는 모여밥 프로젝트의 커밋 메시지 작성 규칙을 정의한다.
2026-08-16부터 적용하며, 이전 커밋에는 소급하지 않는다.

## 형식

```
<type>: <subject>
```

- **type**과 **subject** 사이에 콜론과 공백(`: `)을 넣는다.
- subject는 한국어로 작성한다.
- 끝에 마침표를 붙이지 않는다.
- 한 줄로 작성하며, 50자 이내를 권장한다.

## Type 목록

| type       | 용도                                         | 예시                                        |
|------------|----------------------------------------------|---------------------------------------------|
| `feat`     | 새로운 기능 추가                             | `feat: 팟 채팅 계좌 공유 기능 추가`         |
| `fix`      | 버그 수정                                    | `fix: 마감 시간 계산 오류 수정`             |
| `style`    | UI/CSS 변경 (기능 변화 없음)                 | `style: 현황판 카드 여백 조정`              |
| `refactor` | 코드 구조 변경 (기능·버그 변화 없음)         | `refactor: 팟 상태 관리 로직 분리`          |
| `docs`     | 문서 추가·수정                               | `docs: README 실행 방법 업데이트`           |
| `fix(data)`| 데이터 파일 수정·보정                        | `fix(data): 식당 CSV 누락 항목 추가`        |
| `chore`    | 설정, 의존성, CI 등 코드 외 작업             | `chore: eslint 설정 업데이트`               |
| `test`     | 테스트 추가·수정                             | `test: 팟 생성 API 테스트 추가`             |
| `revert`   | 이전 커밋 되돌리기                           | `revert: 팟 삭제 기능 롤백`                 |

> 애매하면 `feat` 또는 `fix` 중 하나를 고른다. type을 고르느라 시간 쓰지 않는다.

## 하지 않는 것

- 영어 type 외에 본문을 영어로 쓰지 않는다 — 팀 전원이 빠르게 읽을 수 있게 한국어로 통일한다.
- `테스트입니다`, `작업 중`, `수정` 같은 내용 없는 메시지를 쓰지 않는다.
- 하나의 커밋에 관련 없는 여러 변경을 섞지 않는다.

## 커밋 단위

- 하나의 커밋은 하나의 논리적 변경을 담는다.
- 기능 추가와 그에 따른 스타일 변경이 함께라면 하나의 `feat` 커밋으로 묶어도 된다.
- 작업 중간 저장이 필요하면 나중에 `git rebase -i`로 정리한 뒤 push한다.
