### Part 1. 문제 발견 — 3장 · 기준①

핵심 문장은 **"아무도 먼저 제안하지 않는다"**. 최소주문금액·배달비 때문에 같이
시켜야 하는데, 제안하는 사람이 인원 모으기와 정산을 떠안는 구조라 침묵이
반복됩니다. 문제는 두 개 — ⓐ누가 같은 걸 원하는지 모른다 ⓑ조율·정산이
제안자에게 몰린다. (탐색 문제는 배민에서 이미 해결되므로 뺐습니다.)

3번에서 **만들지 않기로 한 것**(메뉴 선택·주문·결제)을 명시합니다. 기준①은
범위를 그은 팀이 유리합니다.

계산합니다.

핵심은 "데이터를 세 종류 모았다"가 아니라 **"단계마다 필요한 데이터가 달라서
세 종류를 설계했다"**로 들리는 것입니다.

### Part 5. 시각화 — 2장 · 기준③④

**11. 무엇을, 왜 그 차트로**

- 시간대별 → 세로 막대 + 피크(11시, 4건)만 주황. 0건 시간대도 지우지 않음.
  **막대 합은 19건** — 9~21시 밖에 열린 팟 1건이 빠져 있으므로 "20건이 다
  여기 있다"고 말하지 말 것
- 카테고리 → 파이가 아니라 가로 바. 7개 항목에 동률이 두 쌍(20% 2개·5% 2개)이라
  파이의 각도로는 구분되지 않음. **"파이를 쓰지 않은 이유"를 말하는 순간
  기준③이 확정됩니다**
- TOP 5 → 차트가 아닌 순위 리스트. 각 행이 클릭 가능한 행동 대상이므로

**12. 행동 데이터를 서비스 기능으로 되돌리기**

- 누적 팟 이력 → 랭킹 · 성사 속도 4지표 · 개인 리포트
- 표본을 정직하게: **"팟 20건 · 누적 참여 78명, 팀이 실제로 쓴 로그"**.
  분모를 먼저 말하고 지표를 말합니다
- 화면 지표: 평균 성사 63.6분 / 최단 25분 / 팟당 3.9명 / 식사:디저트 80:20
- **최단 25분은 실측이 없을 때 서버가 내려주는 기본값과 같은 숫자**입니다.
  발표 직전 `/trends`에서 실제 값인지 확인할 것

### Part 6. AI 활용 — 1장 · 기준⑦

**13. AI, 어디에 썼고 어디서 틀렸나** — 상단 칩 4개(OCR 구조화 / Claude Code 기반
개발 / `AGENTS.md`·`CLAUDE.md` 규칙 고정 / PR 리뷰)는 1초씩만 짚고, 본체는
**AI가 틀린 실제 사례 → 그래서 만든 검수 규칙(`data/DATA_GUIDE.md`)** 두 카드입니다.

기준⑦의 "구체적으로"는 성공담이 아니라 **실패와 개입**을 말할 때 충족됩니다.

**14. AI를 어떻게 지휘했나 — 규칙을 파일로** (신설) — 요건③의 "어떤 프롬프트가
결정적이었나"에 답하는 슬라이드. 핵심 메시지는 **"결정적이었던 건 프롬프트 한
줄이 아니라, 규칙을 파일로 고정한 것"**입니다.

- `CLAUDE.md`는 `@AGENTS.md` **한 줄이 파일 전체** — 도구가 달라도 같은 지침을 봅니다
- `AGENTS.md`에 날짜 도장을 찍은 확정 12건 (2026-08-12 3건 · 08-13 9건)
- "아직 확정하지 않은 사항" 절을 따로 둬서 AI가 빈칸을 추측으로 채우지 못하게 함
- `data/DATA_GUIDE.md`가 데이터 흐름을 한 방향으로 고정 (`app/data/restaurants.ts`는 직접 수정 금지)

> 저장소에 프롬프트 기록이 남아 있지 않아 특정 프롬프트를 인용하지 않았습니다.
> 팀이 기억하는 결정적 프롬프트가 있으면 이 슬라이드에 실물로 넣는 게 더 강합니다.

## 3. 식사 트렌드 페이지 현황

`origin/main`에 머지 완료(PR #7 `feat/stats-report`), `moyeobap.vercel.app/trends`에서
동작합니다. 화면 순서는 **TOP 5 → 시간대별 + 카테고리 → 성사 속도 4지표 →
나의 리포트**이며 슬라이드 11·12가 이 순서를 그대로 따릅니다.

### 발표 전 확인할 것

1. **숫자 대조** — 슬라이드의 20건 / 78명 / 63.6분 / 25분 / 3.9명 / 80:20 /
   카테고리 비중은 발표일 화면과 달라질 수 있습니다. 직전에 `/trends`를 열어
   확인하고, 어긋나면 "오늘 기준" 값으로 말합니다
2. **최단 25분** — 실측이 없으면 서버가 기본값 25를 내려줍니다. 진짜 실측인지 확인
3. **피크 동률** — 11시와 같은 건수의 시간대가 생기면 화면에서 두 막대가 함께
   강조됩니다. "유일한 피크"라고 단정하지 말 것
4. **'기타' 25%의 원인** — ⓐ사용자가 직접 추가한 매장엔 카테고리가 없고,
   ⓑ`getCampusStats`의 키워드 매핑이 표준 소분류 4종(족발·보쌈 5곳 /
   패스트푸드 4 / 찜·탕 4 / 아시안 2, 합 15곳)을 '기타'로 떨어뜨립니다.
   **"조사 데이터가 분류가 안 됐다"가 아니라 "집계 단계의 문제"**로 설명해야
   조사표 슬라이드(배민 14종 고정)와 모순되지 않습니다
