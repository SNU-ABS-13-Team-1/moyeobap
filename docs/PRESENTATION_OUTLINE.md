# 모여밥 발표 구성안

> **문서 상태: 초안 (2026-08-19)**
>
> 15장 / 라이브 시연 3분 15초 / 총 10분 기준.
> 데이터 3분류의 근거는 [DATA_CATEGORIES.md](DATA_CATEGORIES.md)를 따릅니다.

## 0. 평가 기준 (팀 상호평가 반영 항목)

1. 프로젝트가 의미 있는 문제를 명확하게 설정하고 있는가
2. 데이터 수집 및 정제 과정이 충실하게 이루어졌는가
3. 데이터와 전달하려는 메시지에 적합한 차트를 사용했는가
4. 인터랙티비티와 디자인이 사용자의 이해와 탐색을 돕는가
5. 프로젝트 결과물이 실제 웹 환경에 배포되어 정상적으로 작동하는가
6. 웹서비스의 기능, 구성 및 사용성이 완성도 있게 구현되었는가
7. AI를 활용한 구현 과정과 활용 방법을 구체적으로 설명했는가
8. 발표가 명확하고 프로젝트의 핵심 내용을 효과적으로 전달했는가

발표는 결과물만 제시하지 않고 **아이디어 발상 → 데이터 수집 → 구현 → 배포**
전 단계를 순서대로 설명합니다.

**9. 인터랙션 설계 의사결정** — 시연에서 뺀 것을 다이어그램 1장으로

### Part 5. 시각화 — 2장 · 50초 · 기준③④

**10. 무엇을, 왜 그 차트로**

- 시간대별 → 세로 막대 + 피크만 주황. 시간은 순서 있는 축이고, 색을 하나만 쓴
  것은 전할 메시지가 "11시" 하나이기 때문
- 카테고리 → 파이가 아니라 가로 바. 7개 항목 중 6%짜리가 3개라 파이로는 못 읽음.
  **"파이를 쓰지 않은 이유"를 말하는 순간 기준③이 확정됩니다**
- TOP 5 → 차트가 아닌 순위 리스트. 각 항목이 클릭 가능한 행동 대상이므로

**11. 행동 데이터를 서비스 기능으로 되돌리기**

- `PotEvent` 누적 → 랭킹 · 성공률 · 개인 리포트
- 표본을 정직하게: "개설 17 / 완료 17, 2주간 팀 40명 실사용 로그".
  100% 도넛만 띄우면 계산을 의심받습니다. 작은 표본은 숨길 게 아니라
  **진짜 로그라는 증거**로 씁니다

## 2. 라이브 시연 시나리오 (3분 15초)

### 역할 배치

| 역할 | 담당 |
|---|---|
| **팀원A** (폰) | 시연용 팟을 미리 만들어 둠 → 이 팟의 👑 관리자 |
| **발표자** (노트북·화면 미러링) | 팀원A의 팟에 **참여자**로 들어감 |
| **팀원B** (폰) | 두 번째 참여자 (정산 비교용) |

관리자는 **팟을 만든 사람**입니다(`app/lib/backend.ts:67`). 참여만 해서는
관리자가 되지 않습니다.

### 사전 세팅

- 3명 모두 미리 로그인 (무대에서 Google 로그인 실행 금지)
- 팀원A가 시연용 팟 + 진행 중 팟 3~4개 개설 (현황판이 비어 있으면 안 됨)
- 마감 10분 남은 팟 1개 심어두기
- **팀원A 프로필에 은행·계좌 등록** (등록해야 계좌 전송 버튼이 노출됨)
- 배민 함께주문 링크 복사해두기
- 브라우저 줌 133%, 알림 끄기, 탭 1개, BGM OFF
- **전 과정 녹화본 백업**

### A. 현황판 — 30초

1. 로그아웃 상태로 접속 → "로그인 없이도 지금 열린 팟이 다 보입니다"
2. `모집 중 / 마감` 탭(숫자 뱃지) → `점심 / 카페 / 기타` 필터
3. 점심 필터를 건 상태로 → "이 화면을 그대로 Slack에 공유하면, 받은 사람도
   점심 팟만 걸린 채로 열립니다"
4. 마감 탭 → 날짜별로 정리됨

### B. 참여 — 35초

5. 카드 → 상세: 마감 카운트다운 + 최소주문금액 / 예상 배달시간 / 참여인원
   → "몇 명 모여야 시킬 수 있는지가 참여 결정의 전부라, 최소주문금액을 제일
   위에 뒀습니다"
6. 발표자 참여 → 명단에 이름 추가. 👑는 팀원A 옆
   → "관리자는 방을 만든 사람이에요"
7. 팀원B도 폰에서 참여 → 발표자 화면 인원 숫자가 그 자리에서 오름.
   **멘트 없이 화면만 보여줄 것.** 기준⑤가 여기서 증명됩니다

### C. 팟 채팅 & 정산 — 70초 (데모의 중심)

8. 팀원A가 폰에서 메시지 → 발표자 화면에 즉시 도착
9. 팀원A가 **💳 계좌번호 전송** → 발표자 화면 상단에 계좌 배너가 실시간으로
   나타남 → 발표자가 **복사** → "복사됨 ✓"
   → "주문을 대표로 하는 사람이 계좌를 올리면, 대화에 묻히지 않게 항상 위에
   고정됩니다"
10. 발표자가 **배민 함께주문 링크** 붙여넣기 → 자동 하이퍼링크 → 팀원 폰에서
    클릭해 실제로 열림
    → "주문은 배민이 잘합니다. 우리는 거기까지 데려다주는 역할입니다"
11. 발표자만 **💸 송금 완료 표시** → 명단에 발표자 `✓ 송금 완료`,
    팀원B `미송금`
    → "누가 안 냈는지 대표가 일일이 확인하던 걸 화면 하나로" — **문제 ⓒ 회수**
12. 주문 메모 `제육 1개 / 양 많이` → "배민 함께주문 쓰면 안 적어도 된다는
    안내까지"

### D. 새 모집 — 25초 (여기서 발표자가 관리자가 됨)

13. FAB `+` → 음식점 검색 → **"여기 뜨는 112곳이 아까 정제한 그
    데이터입니다"** — Part 3 회수. 반드시 말할 것
14. 카테고리 + 마감 15분~3시간 → 생성
15. 생성 즉시 발표자가 첫 참여자이자 👑 관리자 → 관리자 화면에서 마감 시간 조정
    → "방을 만든 사람이 관리자, 관리자만 마감을 조정합니다" — B의 👑 설명이
    여기서 닫힘

### E. 식사 트렌드 — 35초 (Part 5로 전환)

16. KPI **"함께 아낀 배달비 135,000원"** — Part 1의 문제에 대한 답을 숫자로 회수
17. TOP 5 → **"이 식당으로 팟 열기" 클릭** → 새 모집으로 이동.
    **차트가 보고 끝나지 않고 행동으로 이어지는 장면** (기준③④ 동시 충족)
18. 시간대별 11시 피크 → 나의 리포트

### 시연에서 하지 말 것

- 무대에서 Google 로그인 실행 (팝업·2FA 리스크)
- 참여 취소 / 관리자 자동 승계 시연 → 시간 대비 그림이 안 남음. 슬라이드 9로
- 같은 음식점 중복 팟 경고 → 시연에서 제외
- 개발자도구 열기, 코드 보여주기 (기준⑦에서 따로)
- 3초 이상 막히면 **즉시 녹화본으로 전환**

### 멘트 원칙

**구현 메커니즘은 아키텍처 슬라이드에서만 말하고, 데모 멘트는 사용자가 얻는
것만 말합니다.** 폴링 주기, 낙관적 UI, 정렬 방식 같은 내부 사정은 청중에게
필요한 정보가 아닙니다.

## 3. 식사 트렌드 페이지 (기준③ 대응)

팀원이 제작한 데모 버전이 두 가지 있습니다. **둘을 합친 최종본**을 씁니다.

| 섹션 | v1 | v2 | 최종 |
|---|:---:|:---:|:---:|
| 상단 KPI (아낀 배달비 135,000원 / 누적 17건 / 피크 11시) | ● | | ● |
| 인기 맛집 TOP 5 + "이 식당으로 팟 열기" | ● | ● | ● |
| 시간대별 팟 오픈 막대 + 카테고리 가로 바 | ● | ● | ● |
| 팟 성사 속도 & 성공률 (평균 54.5분 / 최단 25분) | | ● | ● |
| 나의 모여밥 리포트 | ● | ● | ● |

**권장 순서:** KPI → TOP 5 → 시간대별 + 카테고리 → 성사 속도 → 나의 리포트.

v1의 **"함께 아낀 배달비 135,000원"은 반드시 유지**합니다. Part 1에서 정의한
배달비 문제를 얼마나 해결했는지 답하는 유일한 지표이고, 발표 서사가 여기서
닫힙니다.

### 발표 전 손볼 것

1. **성공률 100% 도넛** — 17건 중 17건이면 변별력이 없고 계산을 의심받습니다.
   분모를 노출하는 표기("개설 17 / 완료 17")로 바꾸는 편이 강합니다
2. **"기타" 24%가 공동 1위** — 카테고리 표준화가 덜 됐다는 신호(1회성 직접 추가
   매장이 몰린 것으로 보임). 재분류하거나, 회피하지 말고 먼저 설명할 것
3. **표본 크기** — 17건·62명은 적지만 "2주간 팀 40명 실사용 로그"로 명시하면
   시드 데이터를 쓴 팀들과 갈리는 지점이 됩니다
