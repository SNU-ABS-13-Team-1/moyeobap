# 모여 어플라이 적용 안내

제품 규칙은 [AGENTS.md](../AGENTS.md)의 14절에서 관리합니다.

## 데이터베이스 적용

기존 모여밥 Supabase 프로젝트의 SQL Editor에서
[`20261006000000_moyeo_apply.sql`](../supabase/migrations/20261006000000_moyeo_apply.sql)
전체를 한 번 실행한 뒤 이 브랜치의 앱을 배포합니다. 기존 `auth.users`와
`public.profiles`를 전제로 하며, 새 환경 변수나 외부 서비스는 필요하지 않습니다.
기존 프로젝트에 `schema.sql`을 다시 실행할 필요는 없습니다.

마이그레이션은 기업 목록·제출 테이블과 조회/저장 RPC 두 개를 만듭니다.
기업 목록의 정본은 `public.moyeo_apply_companies`입니다. 화면은 API를 통해
이 테이블을 사용합니다. 기업 추가·이름 변경도 후속 SQL 마이그레이션으로
관리하며, 이미 선택에 사용된 기업 ID는 변경하거나 삭제하지 않습니다.

## 접근과 저장

- `/apply`는 기존 로그인 모달과 로그인 후 복귀 경로를 사용합니다.
- `GET /api/apply`와 `PUT /api/apply` 모두 세션을 확인하고, 사용자 JWT가
  연결된 Supabase 서버 클라이언트로 RPC를 호출합니다. 요청 본문에서 사용자
  ID나 수정 횟수의 새 값을 받지 않습니다.
- DB 함수는 `auth.uid()`로 사용자를 확인합니다. 미제출자의 목록 조회는
  `participants: null`이고, 제출자에게만 표시 이름·지망·본인 여부를 반환합니다.
- 클라이언트 역할의 제출 테이블 직접 조회·추가·수정·삭제는 차단합니다.
  저장 함수가 기업 ID와 연속 순위를 검사하고, 사용자별 잠금 안에서 저장과
  수정 횟수 증가를 처리합니다. 최신 수정 횟수와 다른 변경 요청은 충돌로
  거절하며, 같은 내용을 다시 보내면 횟수를 쓰지 않습니다.
- 개인 응답은 `private, no-store`이며 상시 폴링은 하지 않습니다.

## 핵심 확인

[`supabase/tests/moyeo_apply.sql`](../supabase/tests/moyeo_apply.sql)은 테스트용
Supabase DB에서 마이그레이션 적용 후 실행할 수 있는 SQL 확인 스크립트입니다.
임시 사용자로 저장·재조회, 제출 전후 열람 권한, 2회 수정 한도와 직접 접근 차단을
검사하고 마지막에 롤백합니다. 운영 사용자나 실제 제출 자료로 테스트하지 않습니다.

배포 후에는 테스트 계정 두 개로 Google 로그인 복귀, 최초 제출 후 목록 공개,
두 번 수정 후 편집 잠금 및 계속 열람까지 확인합니다. 이 과정은 로컬 SQL 검증과
별개로 실제 Supabase 세션·배포 연결을 확인하는 절차입니다.

### 2026-10-06 구현 확인 결과

- 프로젝트 의존성을 바꾸지 않고 임시 PGlite 0.5.8(PostgreSQL 18.3)에서
  기존 프로필 마이그레이션, 새 마이그레이션과 위 SQL 검증을 실행해 통과했습니다.
  Supabase의 사용자 테이블과 `auth.uid()`만 최소 테스트 대역을 사용했습니다.
- 저장·재조회, 미제출자/제출자 열람, 2회 수정 제한, 변경 없음·실패·충돌 시
  횟수 보존, 비공개 필드 제외, 직접 조회·수정·삭제 및 익명 RPC 차단을 확인했습니다.
- TypeScript 검사와 변경한 TS/TSX 파일의 ESLint를 통과했습니다. 로컬 Chromium에서
  메뉴 진입, 비로그인 안내, 입력 폼·참여자 표 비노출, API 401 및 `no-store`를 확인했습니다.
- 편의 기능 추가 후 샘플 API 응답을 사용한 Chromium 화면에서 기업순 정렬,
  필터 결과 수·일치 기업 강조·초기화, 빈 순위를 만들지 않는 순위 교환과
  저장 전 요청이 발생하지 않는 것을 확인했습니다. 타입 검사와 ESLint도 통과했습니다.
- 운영 DB 마이그레이션 적용, 실제 Google 로그인과 로그인 후 API 저장 전체 흐름,
  여러 DB 연결에서의 동시 요청은 아직 확인하지 않았습니다.
