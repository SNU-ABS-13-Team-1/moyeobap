서울대학교 시흥캠퍼스 구성원이 음식점별 공동주문 모집을 만들고 참여 현황을
확인할 수 있는 웹앱입니다.

- 배포 상태: 프론트엔드 작업 후 Vercel 배포 예정
- GitHub 저장소: [famegon/moyeobap](https://github.com/famegon/moyeobap)
- 문서 최종 수정일: 2026-08-08

현재 화면에는 확인용 예시 데이터만 포함되어 있습니다.

## 해결하려는 문제

약 40명이 함께 생활하는 교육·연구 공간에서 매일 점심과 카페 주문을 배달로
해결하고 있습니다. 현재는 다음과 같은 불편이 있습니다.

- 누가 어느 음식점을 원하는지 알기 어렵습니다.
- 공동주문에 필요한 인원이 모였는지 확인하기 어렵습니다.
- 주문을 제안하거나 주문방을 만드는 사람에게 부담이 집중됩니다.
- 최소 주문금액, 배달비와 실제 주문 담당자를 따로 조율해야 합니다.

모여밥은 사용자가 음식점과 모집 마감 시간을 등록하고, 다른 사용자가 실시간
현황판을 확인해 공동주문에 참여할 수 있는 방식을 목표로 합니다.

## 핵심 이용 흐름

사용자는 Slack 공지 링크에서 로그인 없이 실시간 모집을 확인하고, Slack
인증 후 참여하거나 새 모집을 만듭니다. 모집이 마감되면 참여자 전용 Slack
대화로 이동해 실제 주문을 논의합니다. 상세 운영 규칙과 남은 설계 질문은
[모여밥 작업 지침서](AGENTS.md)를 확인합니다.

## 현재 프로토타입에서 확인할 수 있는 기능

- 로그인 없이 보는 실시간 공동주문 현황판
- 전체 모집과 내 참여 보기 전환
- 점심과 카페 모집 전환
- 음식점과 카테고리 검색
- 모집 마감 시간이 가까운 순서로 정렬
- 현황판의 빠른 참여와 모집 상세 이동
- 모집 상세의 매장 정보와 대표메뉴 최대 5개 표시
- 참여 후 참여자 이름과 모집 관리자 확인
- 공동주문 참여 및 참여 취소
- 음식점, 주문 종류와 모집 마감 시간을 입력하는 별도 모집 생성 화면
- 같은 음식점의 진행 중 모집과 동일 마감 중복 확인
- 모집 생성자의 첫 참여자 자동 등록
- 모집 관리자 이탈 시 참여 순서에 따른 자동 이임
- Slack 로그인과 참여자 대화 흐름의 위치 확인
- 모바일과 PC에 대응하는 반응형 화면

## 현재 구현 상태

| 항목 | 현재 상태 |
|---|---|
| 음식점·모집 데이터 | 화면 확인용 예시 데이터 |
| 참여·관리자 이임·새 모집 | 브라우저 화면에만 임시 저장 |
| 새로고침 후 변경사항 | 초기화됨 |
| 실시간 다중 사용자 반영 | 미구현 |
| Slack 로그인 | 화면 위치만 표시, 실제 연동 미구현 |
| Slack 알림·대화 공간 | 미구현 |
| 실제 주문·결제 | 미연동 |
| 정산 | 미구현 |
| 주문 담당자 선정 | 참여자들이 Slack에서 논의할 예정 |

현재 버전은 서비스 방향과 화면 흐름을 검증하기 위한 프로토타입입니다. 실제
운영 전에는 데이터베이스, Slack 인증, 실시간 참여 동기화와 운영 규칙을
추가해야 합니다.

현재 화면은 합의한 User Flow와 정보 구조를 검증하기 위한 mid-fi
프로토타입입니다. 실제 인증, 마감 자동 처리와 Slack 인계는 아직 연결하지
않았습니다.

## 음식점·메뉴 데이터 작성

팀원들이 수집한 자료는 원본과 앱에서 사용하는 정리본을 구분합니다. 데이터를
추가하거나 수정하기 전에는 [상세 데이터 작성 가이드](data/DATA_GUIDE.md)의
파일 형식과 검수 기준을 확인해 주세요.

```text
data/
├─ raw/                  팀원들이 수집한 원본 파일
├─ restaurants.csv      검토가 끝난 음식점·카페 정보
├─ menus.csv            검토가 끝난 메뉴·가격 정보
├─ sources.csv          출처와 확인 날짜
└─ DATA_GUIDE.md        데이터 입력 및 검수 규칙
```

앱용 데이터는 음식점·카페와 메뉴를 각각 `restaurants.csv`와 `menus.csv`로
분리하고 `restaurant_id`로 연결합니다. 메뉴 화면에는 이미지, 이름과 가격만
표시합니다.

핵심 작성 규칙:

- 음식점과 메뉴 ID는 중복 없이 작성하고 임의로 변경하지 않습니다.
- 가격에는 쉼표나 `원`을 붙이지 않고 숫자만 입력합니다.
- 단품 주문이 불가능한 샷·시럽·휘핑 등의 추가 옵션은 메뉴에서 제외합니다.
- 출처와 가격 확인 날짜를 `sources.csv`에 기록합니다.
- 확인하지 못한 값은 추측하지 않고 비워둡니다.
- 이미지 사용 권한을 확인하고 최종 데이터에는 허용된 로컬 경로나 `https`
  주소만 사용합니다.
- 계정 비밀번호, API 키, 계좌번호 등 개인정보나 민감정보를 올리지 않습니다.

## 로컬 실행 방법

### 준비 사항

- Node.js 22.13 이상
- npm

### 실행

```bash
npm install
npm run dev
```

터미널에 표시되는 로컬 주소를 브라우저에서 엽니다.

### 배포용 빌드 확인

```bash
npm run build
```

## Vercel 배포

GitHub 저장소에 변경사항을 올린 뒤 Vercel에서 해당 저장소를 가져옵니다.
Vercel이 Next.js 프로젝트를 자동으로 인식하므로 별도의 빌드 설정을 추가하지
않고 배포할 수 있습니다. 이후 GitHub에 변경사항을 올리면 연결된 Vercel
프로젝트가 자동으로 다시 배포됩니다.

## 프로젝트 구조

```text
moyeobap/
├─ app/
│  ├─ components/        공통 헤더, 모집 카드와 알림
│  ├─ lib/               예시 음식점·모집 데이터와 타입
│  ├─ recruitments/
│  │  ├─ [id]/page.tsx   모집 상세
│  │  └─ new/page.tsx    새 모집 만들기
│  ├─ page.tsx           실시간 현황판
│  ├─ prototype-context.tsx  화면 간 공유 프로토타입 상태
│  ├─ globals.css        전체 화면 스타일
│  └─ layout.tsx         페이지 정보와 공유 이미지 설정
├─ public/
│  └─ og-v2.png          링크 공유 미리보기 이미지
├─ data/
│  └─ DATA_GUIDE.md      음식점·메뉴 데이터 작성 및 검수 기준
├─ package.json
├─ next.config.ts
└─ README.md
```

현재 예시 음식점과 모집은 `app/lib/prototype-data.ts`에 들어 있습니다. 실제
데이터를 연결할 때는 검수된 데이터 파일 또는 데이터베이스로 교체할
예정입니다.
